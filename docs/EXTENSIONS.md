# mica: совместимость расширений

Проверенная платформа: macOS 15.7.5, системный WebKit, Xcode 26.1 SDK, 7 ноября 2026 года. Наличие WebExtensions API не означает совместимость всех API других браузеров.

## Источники

Firefox Add-ons: поиск использует документированный [GET /api/v5/addons/search/](https://mozilla.github.io/addons-server/topics/api/addons.html), HTTPS и непостоянную URLSession без авторизации. Каталог пуст до явного поиска; отсутствие сети и ошибки показываются. Результат ведёт на оригинальную карточку, где доступны автор и лицензия. Встроенный каталог не объявляет результат проверенным или установленным по факту нахождения.

Установка из каталога (с версии 0.2.0): по нажатию пользователя mica скачивает файл из поля `current_version.file.url` того же ответа API, только с `https://addons.mozilla.org`, ограничивает размер 64 МБ и сравнивает SHA-256 с полем `file.hash`. При несовпадении установка отменяется. Дальше пакет проходит обычный импорт: проверка архива, показ прав и согласие до запуска кода. Это загрузка опубликованного Mozilla пакета для одного пользователя по его действию, так же как кнопка на сайте AMO; mica не хранит и не перераспространяет чужие пакеты. Кнопка «обновить до» появляется, если найденная версия отличается от установленной. Подпись Mozilla внутри XPI WebKit не проверяет; целостность обеспечивает HTTPS к AMO и совпадение хеша. 8 ноября 2026 года проверено вне приложения: для расширения оформления 4.9.135 API вернул ссылку на addons.mozilla.org, загрузка дала HTTP 200, 909302 байта, SHA-256 совпал с `file.hash`. Полный путь кнопки в приложении с ответом на запрос прав в этой сессии не прокликивался.

Chrome Web Store (с 8 ноября 2026 года): по действию пользователя mica запрашивает `https://clients2.google.com/service/update2/crx` с `acceptformat=crx3` и ID расширения, тот же адрес обновлений, который использует Chrome и браузеры на Chromium. Ответ ограничен 64 МБ. `CRXPackage` (`Sources/MicaCore/ChromeStore.swift`) разбирает заголовок CRX3, берёт ID из подписанного заголовка, сверяет его с запрошенным и проверяет подпись SHA256-with-RSA (или ECDSA) ключом, из которого этот ID получается. Подпись Google-ключа магазина не проверяется. После проверки ZIP проходит обычный импорт с показом прав. Источник записывается как `cws:<id>`; повторная установка того же ID обновляет пакет с сохранением хранилища. Скрейпинга за авторизацией и обхода проверки клиента нет. Ограничение: работают только API, которые реализует WebKit, а WebKit на этой системе не даёт, например, `offscreen` и `userScripts`.

## Импорт и права

Поддерживаются папка с корневым `manifest.json` и ZIP/XPI. CRX3 принимается только из Chrome Web Store по ID, после проверки подписи; локальный CRX-файл не импортируется. Объём архива ограничен 64 МБ, распакованный объём — 128 МБ, число элементов — 10000. До распаковки проверяются пути, объём и символические ссылки; после — дерево файлов. Вывод архивного инструмента и время его работы ограничены. Проверка и SHA-256 выполняются вне main actor, хешируется поток по 64 КиБ.

Встроенные `zipinfo` и `ditto` запускаются с массивом аргументов, без shell-интерполяции. Содержимое расширения не запускается как нативный исполняемый файл. Само расширение читается публичным WKWebExtension из копии в sandbox-контейнере. Ресурсы не изменяются для подделки совместимости.

Импорт показывает описание, доступные WebKit API, запрашиваемые origins, отсутствующие возможности и SHA-256 локального дерева. Эта сумма проверяет неизменность локальной копии при следующих запусках. Она не удостоверяет издателя и не является проверкой подписи AMO или CRX. До согласия контекст расширения не загружается.

Замечания WebKit к манифесту (`WKWebExtension.errors`) не останавливают импорт: WebKit пропускает ошибочную запись и загружает остальное, как Safari. Импорт и карточка расширения показывают их строкой «WebKit пропустил часть манифеста». Частый случай: пустая команда `"_execute_browser_action": {}` или `"_execute_action": {}` в `commands`, допустимая в Firefox и Chrome. До 12 ноября 2026 года mica считала любое такое замечание фатальным, и uBlock Origin 1.76.0 и Block Site 0.6.2 не ставились с ошибкой «Пустая или недействительная команда в записи `commands`». Проверено вне приложения: оба пакета после замечания загружаются в `WKWebExtensionController`.

Блокировщики на Manifest V2 с `webRequestBlocking` (AdGuard, Ghostery, AdBlocker Ultimate, AdBlock, DuckDuckGo) в WebKit фильтровать запросы не могут: публичный `WKWebExtension` не даёт расширению отменять запросы. Каталог отмечает их до загрузки и не показывает кнопку установки, импорт с диска отклоняет и указывает на встроенную блокировку в настройках.

## Встроенная блокировка на базе uBlock Origin

В разделе «поиск и защита» один переключатель управляет встроенной блокировкой. Устанавливать расширение не нужно: компоненты uBlock Origin 1.76.0, проверенные по SHA-256 официального XPI из AMO, находятся в `shared/blocking/ublock`. Лицензии и источники перечислены в `shared/blocking/NOTICE.txt`; восстановление закреплённой версии: `python3 scripts/vendor-ublock.py`. Общий модуль `shared/blocking/compiler.mjs` вызывает собственный компилятор uBO `dnrRulesetFromRawLists` и `make-scriptlets.js` (тот же конвейер, из которого собирается uBO Lite). На macOS результат применяется публичным WebKit:
1. сетевые правила DNR переводятся в регулярные выражения content rule list (`||`, `^`, `|`, `*`, домены инициатора, тип ресурса, сторонность); правила с методами, заголовками, перенаправлениями и исключёнными доменами запроса пропускаются;
2. общие и точечные правила скрытия становятся `css-display-none`, селектор проверяет сам WebKit, процедурные правила uBO (`:has-text` и подобные) пропускаются;
3. скриптлеты собираются в два пакета и встраиваются в начале документа во все фреймы: в мир страницы и в изолированный мир `mica-ublock`. Именно они убирают рекламу YouTube.

Списки: значения по умолчанию из `assets/assets.json` пакета, кроме urlhaus (около 200 тысяч хостов вредоносных сайтов удвоили бы набор правил без пользы против рекламы). Сначала берутся встроенные копии, затем раз в сутки и по кнопке «обновить» в настройках они скачиваются из источников uBO (CDN первым) без cookie. Сборка кэшируется по отпечатку пакета, списков, исключений сайтов и версии компилятора. Исключения сайтов из настроек блокировки (`blockingExceptions`) действуют и на uBO. Группа «сайты без блокировки» всегда показывает поле добавления домена; добавленные домены можно удалить. Исключение распространяется на сам домен и его поддомены, включая базовый движок и скриптлеты. После изменения нужно перезагрузить страницу. Сведения о сайте показывают унаследованное исключение; включение блокировки там снимает совпадающие родительские исключения. Фильтры применяются и в приватных окнах: они только убирают содержимое. Всплывающее окно, панель и пипетка uBO недоступны. Старая запись uBlock Origin переносится в эту настройку с сохранением enabled и исключений, пакет остаётся на диске для восстановления. Повторный импорт предлагает настройки. Базовый список доменов используется только до готовности расширенного движка или при ошибке; одновременно два набора не применяются. Окно появляется сразу, первые навигации ждут завершения первой подготовки фильтров.

На Windows временный невидимый контроллер WebView2 компилирует те же списки через локальный виртуальный хост, доступ к внешним ресурсам этой страницы запрещён. После компиляции контроллер закрывается. Сетевой адаптер `ContentRules` использует индекс доменов, ограниченное время регулярного выражения и встроенный Public Suffix List. Правила скрытия становятся CSS, скриптлеты устанавливаются через `AddScriptToExecuteOnDocumentCreatedAsync` во всех фреймах, в том числе инкогнито. Публичный API WebView2 исполняет оба пакета скриптлетов в мире страницы, каждый в своей функции, отдельного изолированного мира здесь нет. Обновление списков, кэш, выключение и исключения управляются настройками mica. Windows собрана на Mac; установка скриптов, фильтрация живых запросов, YouTube и интерфейс на машине Windows ещё не проверены.

Автоматические проверки: `node scripts/tests/blocking.mjs` проверяет настоящий компилятор из пакета (сеть, разрешающие правила, CSS, скриптлеты, исключения). Его фиксированный сетевой результат из `shared/fixtures/blocking/compiled.json` используется C#-тестами адаптера. Обновление фикстуры: `MICA_WRITE_BLOCKING=1 node scripts/tests/blocking.mjs`. Адаптер относится к публичным API платформы, правила общего ядра не изменялись.

Проверено 12 ноября 2026 года, uBlock Origin 1.76.0 из AMO. Вне приложения, отдельный `WKWebView` на двух роликах YouTube: без фильтров `ytInitialPlayerResponse` содержит рекламу, плеер в режиме `ad-showing` и ролик стоит на 0 с все 26 секунд; со скриптлетами и правилами рекламы нет, ролик играет с первых секунд. В mica (`--qa --ublock-check`, вкладка обычного окна, регион FR, cookie отказа на странице согласия): без uBO и без uBO Lite реклама есть, с uBO в двух прогонах её нет, во вкладке оба пакета скриптлетов. Сборка: около 120 тысяч сетевых правил, 7,3 тысячи правил скрытия, 5,3 тысячи скриптлетов; компиляция WebKit около 7 с при первой сборке, далее из кэша. Не проверены: переходы между роликами без перезагрузки, YouTube Music и мобильная версия, страницы, где WebKit отвергнет конкретное правило.

Иконки: каталог берёт `icons["64"]` из ответа AMO только с `https://addons.mozilla.org`, без cookie; установленные расширения показывают иконку из пакета, выключенные тоже (пакет читается, код не запускается).

Можно установить без доступа к сайтам или выдать заявленный доступ, затем разрешить текущий сайт отдельно и отозвать hosts через управление. Runtime-запросы дополнительных прав идут через делегат и требуют решения пользователя. URL-разрешение, выданное как «один раз», ограничено пятью минутами. Private data не выдаются, а private WKWebView вообще не подключены к контроллеру. Native messaging не реализован и не выдаётся.

Включение выполняет `controller.load`, выключение — `unload`. Нет скрытого запуска выключенного расширения. Удаление удаляет локальный пакет и данные контекста через API WebKit. Обновление с диска повторно показывает права, сохраняет identifier/storage и откатывает пакет при ошибке загрузки. Автоматических сетевых обновлений расширений нет.

Удаление/отзыв доступа не обещает отменить уже выполненные изменения сайта. mica не перезагружает живые страницы принудительно. При необходимости пользователь сам перезагружает страницу.

## Мост браузера

Реализованы публичные протоколы окон и вкладок, список открытых обычных окон, выбранная вкладка, URL, заголовок, индекс, pinned, loading, размер, zoom, выбор/закрытие, создание вкладок и окон, options page и popup. Отправляются события открытия, закрытия, выбора, перемещения, закрепления и завершения загрузки. Контроллер указан в WKWebViewConfiguration, поэтому WebKit может связывать вкладку с content scripts и tab APIs.

Изменение native browser theme расширениями не реализовано. Набор поддерживаемых API ограничен WebKit. Запрошенные обязательные `downloads`, `identity`, native messaging и другие критические отсутствующие API приводят к отказу установки, а не к показу работающей функции. Поддержку необязательных функций нельзя вывести из успешного чтения manifest.

Контекстные меню сайта предоставляет WebKit. Пользовательские пункты расширений в контекстном меню сайта, расширенные операции перемещения вкладок между окнами, native messaging, DevTools extensions и расширенные browser-theme API не подтверждены как поддерживаемые этой оболочкой. Поддержка этих возможностей не заявляется.
