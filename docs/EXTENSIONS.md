# mica: совместимость расширений

Проверенная платформа: macOS 15.7.5, системный WebKit, Xcode 26.1 SDK, 7 ноября 2026 года. Наличие WebExtensions API не означает совместимость всех API Chrome, Firefox или Safari.

## Источники

Firefox Add-ons: поиск использует документированный [GET /api/v5/addons/search/](https://mozilla.github.io/addons-server/topics/api/addons.html), HTTPS и непостоянную URLSession без авторизации. Каталог пуст до явного поиска; отсутствие сети и ошибки показываются. Результат ведёт на оригинальную карточку, где доступны автор и лицензия. Встроенный каталог не объявляет результат проверенным или установленным по факту нахождения.

Установка из каталога (с версии 0.2.0): по нажатию пользователя mica скачивает файл из поля `current_version.file.url` того же ответа API, только с `https://addons.mozilla.org`, ограничивает размер 64 МБ и сравнивает SHA-256 с полем `file.hash`. При несовпадении установка отменяется. Дальше пакет проходит обычный импорт: проверка архива, показ прав и согласие до запуска кода. Это загрузка опубликованного Mozilla пакета для одного пользователя по его действию, так же как кнопка на сайте AMO; mica не хранит и не перераспространяет чужие пакеты. Кнопка «обновить до» появляется, если найденная версия отличается от установленной. Подпись Mozilla внутри XPI WebKit не проверяет; целостность обеспечивает HTTPS к AMO и совпадение хеша. 8 ноября 2026 года проверено вне приложения: для Dark Reader 4.9.135 API вернул ссылку на addons.mozilla.org, загрузка дала HTTP 200, 909302 байта, SHA-256 совпал с `file.hash`. Полный путь кнопки в приложении с ответом на запрос прав в этой сессии не прокликивался.

Chrome Web Store (с 8 ноября 2026 года): по действию пользователя mica запрашивает `https://clients2.google.com/service/update2/crx` с `acceptformat=crx3` и ID расширения, тот же адрес обновлений, который использует Chrome и браузеры на Chromium. Ответ ограничен 64 МБ. `CRXPackage` (`Sources/MicaCore/ChromeStore.swift`) разбирает заголовок CRX3, берёт ID из подписанного заголовка, сверяет его с запрошенным и проверяет подпись SHA256-with-RSA (или ECDSA) ключом, из которого этот ID получается. Подпись Google-ключа магазина не проверяется. После проверки ZIP проходит обычный импорт с показом прав. Источник записывается как `cws:<id>`; повторная установка того же ID обновляет пакет с сохранением хранилища. Скрейпинга за авторизацией и обхода проверки клиента нет. Ограничение: работают только API, которые реализует WebKit, а WebKit на этой системе не даёт, например, `offscreen` и `userScripts`.

## Импорт и права

Поддерживаются папка с корневым `manifest.json` и ZIP/XPI. CRX3 принимается только из Chrome Web Store по ID, после проверки подписи; локальный CRX-файл не импортируется. Объём архива ограничен 64 МБ, распакованный объём — 128 МБ, число элементов — 10000. До распаковки проверяются пути, объём и символические ссылки; после — дерево файлов. Вывод архивного инструмента и время его работы ограничены. Проверка и SHA-256 выполняются вне main actor, хешируется поток по 64 КиБ.

Встроенные `zipinfo` и `ditto` запускаются с массивом аргументов, без shell-интерполяции. Содержимое расширения не запускается как нативный исполняемый файл. Само расширение читается публичным WKWebExtension из копии в sandbox-контейнере. Ресурсы не изменяются для подделки совместимости.

Импорт показывает описание, доступные WebKit API, запрашиваемые origins, отсутствующие возможности и SHA-256 локального дерева. Эта сумма проверяет неизменность локальной копии при следующих запусках. Она не удостоверяет издателя и не является проверкой подписи AMO или CRX. До согласия контекст расширения не загружается.

Можно установить без доступа к сайтам или выдать заявленный доступ, затем разрешить текущий сайт отдельно и отозвать hosts через управление. Runtime-запросы дополнительных прав идут через делегат и требуют решения пользователя. URL-разрешение, выданное как «один раз», ограничено пятью минутами. Private data не выдаются, а private WKWebView вообще не подключены к контроллеру. Native messaging не реализован и не выдаётся.

Включение выполняет `controller.load`, выключение — `unload`. Нет скрытого запуска выключенного расширения. Удаление удаляет локальный пакет и данные контекста через API WebKit. Обновление с диска повторно показывает права, сохраняет identifier/storage и откатывает пакет при ошибке загрузки. Автоматических сетевых обновлений расширений нет.

Удаление/отзыв доступа не обещает отменить уже выполненные изменения сайта. mica не перезагружает живые страницы принудительно. При необходимости пользователь сам перезагружает страницу.

## Мост браузера

Реализованы публичные протоколы окон и вкладок, список открытых обычных окон, выбранная вкладка, URL, заголовок, индекс, pinned, loading, размер, zoom, выбор/закрытие, создание вкладок и окон, options page и popup. Отправляются события открытия, закрытия, выбора, перемещения, закрепления и завершения загрузки. Контроллер указан в WKWebViewConfiguration, поэтому WebKit может связывать вкладку с content scripts и tab APIs.

Изменение native browser theme расширениями не реализовано. Набор поддерживаемых API ограничен WebKit. Запрошенные обязательные `downloads`, `identity`, native messaging и другие критические отсутствующие API приводят к отказу установки, а не к показу работающей функции. Поддержку необязательных функций нельзя вывести из успешного чтения manifest.

Контекстные меню сайта предоставляет WebKit. Пользовательские пункты расширений в контекстном меню сайта, расширенные операции перемещения вкладок между окнами, native messaging, DevTools extensions и расширенные browser-theme API не подтверждены как поддерживаемые этой оболочкой. Для них не заявляется паритет с Chrome/Firefox.
